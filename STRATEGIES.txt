1. STRATEGIC PILLAR — PLAIN ENGLISH
================================================================================

“Strategic” here does NOT mean discretionary guessing.
It means: a REPEATABLE research factory that turns hypotheses into
versioned models that may only trade after gates.

CORE LOOP (memorize this)
  Hypothesis
    -> Features (point-in-time, no lookahead)
    -> Offline train (classical ML / stats)
    -> Cost-aware walk-forward validation
    -> Paper (same code as live)
    -> Loss Prediction check + Risk Kernel
    -> Tiny live
    -> Scale only on capacity
    -> Scheduled retrain / decay monitor / kill if dead

WHAT “EDGE” MEANS
  After brokerage + STT + slippage + lot constraints, the strategy still
  shows honest out-of-sample risk-adjusted performance under our ceilings.
  Pretty backtests without costs are worthless.

3. OFFLINE MODELS vs ONLINE APIs vs HYBRID — DECISION
================================================================================

VERDICT FOR PROJECT ALPHA: HYBRID (with hard boundaries)

  LAYER A — ALPHA + LOSS FORECASTS  = OFFLINE (local packages, free)
  LAYER B — ENGINEERING + RESEARCH  = ONLINE (Cursor Pro+ / LLM APIs)
  LAYER C — NEWS INTELLIGENCE       = ONLINE LLM + parsers + verification
  LAYER D — RISK / SIZE / HALT      = DETERMINISTIC CODE (never LLM)

WHY NOT “ONLINE API MODELS FOR TRADING SIGNALS”
  - Cost burns every inference / every tick narrative
  - Non-reproducible (model versions change behind API)
  - Hard to audit for SEBI/broker / your own trial registry
  - Weak for tabular mid-freq vs gradient boosting on good features
  - Latency + outage risk on the critical path

WHY NOT “ONLY OFFLINE EVERYTHING”
  - Your team velocity collapses without Cursor/LLMs for code/tests/docs
  - News/filings extraction is painful without LLMs (but must be verified)

WHY HYBRID IS BEST + COST-EFFECTIVE
  - Train LightGBM once offline (cheap CPU) -> serialize -> local infer
  - Spend API money where ROI is highest: building correct software
  - Accuracy for mid-freq tabular alpha is NOT improved by GPT on the order path

4. OFFLINE MODELS TO INSTALL / DOWNLOAD (FREE)
================================================================================

These are libraries you `pip install` — NOT paid “trading AI” products.
There is no magic pretrained “NSE alpha model” you should blindly download
and trust with capital.

A. SIGNAL / ALPHA MODELS (install)
  Package        Role                              License / cost
  -------------  --------------------------------  ---------------
  scikit-learn   Ridge, ElasticNet, logistic,      BSD / FREE
                 calibration, pipelines
  lightgbm       Primary nonlinear tabular alpha   MIT / FREE
  xgboost        Alternate GBDT                    Apache-2 / FREE
  statsmodels    ARIMA-ish, regression, diagnostics BSD / FREE
  arch           GARCH / vol models                FREE
  numpy/scipy    Math core                         FREE
  pandas/polars  Feature tables                    FREE
  joblib         Model serialize                   FREE
  pyarrow        Parquet I/O                       FREE

B. LOSS PREDICTION MODELS (same stack)
  - Calibrated classifier / GBDT predicting:
      P(hit daily loss stop | setup, regime, size)
      Expected shortfall / adverse move over horizon
  - Train offline on historical path outcomes AFTER costs
  - Serialize separately from alpha model (own version + hash)

C. REGIME / FILTERS
  - Simple: realized vol, trend slope, ADX-like features, session flags
  - Optional HMM / simple state filter (statsmodels / hmmlearn) — later

D. WHAT NOT TO DOWNLOAD FOR Y1 ALPHA
  - Random GitHub “AI stock predictor” weights
  - Finetuned LLM trading checkpoints for live sizing
  - Heavy deep learning tick models (need different hardware justification)

INSTALL BASELINE (research machine)
  python -m pip install --upgrade pip
  pip install numpy scipy pandas polars pyarrow scikit-learn \
              lightgbm xgboost statsmodels arch joblib matplotlib \
              pytest duckdb

Optional later: hmmlearn, optuna (hyperparam search — careful with overfitting)

7. HOW WE TRAIN / FEED STRATEGIES (STEP BY STEP)
================================================================================

STEP 1 — HYPOTHESIS CARD (human or Strategy Research Agent draft)
  Fields: thesis, universe, horizon, features sketch, risk notes, reject criteria
  Manager accepts into trial registry (status=INTAKE)

STEP 2 — DATA
  Pull OHLCV (+ OI for F&O) point-in-time
  Apply corp actions / continuous futures rules
  Write Parquet partitions; golden-file tests

STEP 3 — FEATURES
  Build matrix X_t using only info available at t
  Freeze feature schema before OOS evaluation

STEP 4 — LABELS
  Example: forward net return over H bars AFTER cost model
  Loss labels: did path hit stop / ES over horizon

STEP 5 — OFFLINE TRAIN (high-end PC)
  Walk-forward / purged CV
  Models: Ridge baseline -> LightGBM primary
  Log all trials (params, metrics, reject/promote)

STEP 6 — SERIALIZE ARTIFACT
  Bundle: model file + feature schema + train window + metrics + content hash
  Store immutable; only promoted hashes may go paper/live

STEP 7 — PAPER
  Same code path; Loss + Risk on
  Measure shortfall, misses, loss-block outcomes

STEP 8 — LIVE INFER
  Load promoted artifact
  Score on live features
  Portfolio draft -> Loss Prediction -> Risk Kernel -> Manager -> Execution

STEP 9 — SCHEDULED RETRAIN
  Weekly or monthly batch on high-end PC
  New artifact must re-pass gates (no silent replace)
